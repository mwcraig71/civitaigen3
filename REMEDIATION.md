# CivitAiGen2 — Security Remediation & Applied Fixes

Date: July 5, 2026

## STEP 0 — Do these on GitHub before pushing anything

1. **Make the repo private** (Settings → General → Danger Zone → Change visibility).
   `generations_export.json` (16 MB of user IDs + prompts) has been public.

2. **Purge sensitive files from git history.** Deleting them in a commit is NOT
   enough — they remain in every old commit. From a **fresh clone**:

   ```bash
   pip install git-filter-repo

   git clone https://github.com/mwcraig71/CivitAiGen2.git CivitAiGen2-purge
   cd CivitAiGen2-purge

   git filter-repo \
     --invert-paths \
     --path generations_export.json \
     --path image_urls_for_migration.json \
     --path characters_import.sql \
     --path copy_characters_to_production.sql \
     --path cookies.txt \
     --path migration_summary.json \
     --path attached_assets

   git remote add origin https://github.com/mwcraig71/CivitAiGen2.git
   git push origin --force --all
   git push origin --force --tags
   ```

   Note: `attached_assets/` (screenshots/log dumps, most of the 398 MB) is
   included in the purge above. Copy anything you still need out of it first.

3. **Rotate everything that ever appeared in the repo or its history**:
   SESSION_SECRET, any CivitAI/Replicate/Stripe/Gemini/NOWPayments keys that
   were in committed files or logs, and any session cookies (cookies.txt).

4. GitHub caches force-pushed commits. After purging, contact GitHub Support
   to clear cached views, or at minimum confirm old commit SHAs 404.

## STEP 1 — Apply the code fixes

The patch in this folder (`civitaigen2-fixes.patch`) applies all changes below.
From your repo root (after the history purge):

```bash
git checkout -b security-fixes
bash cleanup.sh                          # removes data exports + dead files first
git apply --index civitaigen2-fixes.patch
npm install        # picks up helmet, cors, express-rate-limit; drops fake "crypto"
npm test           # 10 smoke tests should pass
```

The patch excludes `package-lock.json` (regenerated by `npm install`) and the
file deletions (handled by `cleanup.sh` so the diff stays reviewable).

Verification already done on this exact patch: 10/10 vitest tests pass,
eslint 0 errors, and `tsc` reports the SAME 367 pre-existing errors as the
untouched repo — zero new type errors introduced (per-file/per-code counts
compared). The CI type-check step is `continue-on-error` until that backlog
is burned down; lint and tests are blocking.

## STEP 2 — New required environment variable

```bash
openssl rand -hex 32   # -> set as ENCRYPTION_KEY
```

- **ENCRYPTION_KEY is now required in production.** The server refuses to boot
  without it (fail-closed, by design).
- Existing stored API keys (old createCipher/CBC format) still decrypt via a
  compatibility path and are **automatically re-encrypted to AES-256-GCM the
  next time each key is read**. No manual migration needed, but keep
  SESSION_SECRET unchanged until all rows have migrated (the legacy decrypt
  derives from it). To force-migrate everything at once, call
  `storage.getUserApiKey(userId)` for each user with a non-null key.

## What was changed

### Critical
- **Encryption rewritten** (`server/crypto.ts`, new): AES-256-GCM via
  `createCipheriv`, random 12-byte IV, auth tag, dedicated ENCRYPTION_KEY.
  Legacy ciphertexts decrypt through an EVP_BytesToKey compatibility shim
  (createDecipher was removed in Node 22) and lazily re-encrypt on read.
- **Fake `crypto` npm package removed** from dependencies (typo-squat risk;
  Node's built-in is used).
- **`DELETE /api/admin/clear-storage` had NO authentication** — anyone could
  wipe all image storage. Now behind `requireAdmin`. (Not in the original review.)
- **`POST /api/admin/manual-credit-fix` let ANY logged-in user grant
  themselves 100 credits** — only checked isAuthenticated. Now `requireAdmin`.
  Consider auditing credit_transactions for abuse. (Not in the original review.)

### High
- **Admin auth standardized**: the two duplicate middlewares (`requireAdmin`,
  `isAdmin`) merged into one `server/middleware.ts`; 15 routes converted or
  newly protected (object-storage browse/stats, bot accounts, impersonate,
  cleanup-deprecated-models). `stop-impersonate` / `impersonation-status`
  intentionally stay on `isAuthenticated` — during impersonation the session
  user is not an admin.
- **Logger with redaction** (`server/logger.ts`, new): leveled (LOG_LEVEL),
  redacts api keys / bearer tokens / passwords / Stripe keys. All 793
  `console.*` calls across `server/` converted. Response bodies are no longer
  captured into request logs (they contained prompts).
- **Sensitive + dead files deleted** from the working tree: both data exports,
  both SQL dumps, cookies.txt, migration_summary.json, 4 backup/dead page
  files, the 19k-line migration script. `.gitignore` extended to keep them out.

### Medium
- **helmet** added (CSP off for now — the SPA loads external assets; add a real
  CSP as a follow-up).
- **CORS fixed**: was `Access-Control-Allow-Origin: *`; now same-origin plus an
  ALLOWED_ORIGINS allowlist, with credentials support.
- **Rate limits**: global 300/min/IP on /api, 20/15min on login endpoints,
  30/min on generation endpoints (tune to taste).
- **API cache headers fixed**: `/api/*` was sent with `Cache-Control: public,
  max-age=60` — shared caches could serve one user's data to another. Now
  `no-store`. (Not in the original review.)
- **Error handler no longer rethrows** after responding (was a process-crash
  vector on any request error).
- **.env.example** added covering all 26 env vars actually referenced.
- **CI** (`.github/workflows/ci.yml`): tsc + eslint + vitest on push/PR.
- **eslint + prettier** configs added; `no-console` is an error in `server/`.
- **Tests** (`server/__tests__/`): encryption round-trip, IV randomness, GCM
  tamper rejection, legacy-format decryption, logger redaction.
- Package renamed `rest-express` → `civitaigen2`; stale "in-memory storage"
  doc line in replit.md corrected.
